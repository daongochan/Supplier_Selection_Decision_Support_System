## 3. Detailed Technical Analysis & Remediations

### 3.1. F01 & F08 — Safe DOM Rendering & Async Race Protection (`Views/EvaluationBatch/Create.cshtml`)
- **Root Cause:** When the user selected a `ProductGroup`, the `change` handler fetched `/EvaluationBatch/SuppliersByGroup?groupId=...` and built `<label class="selection-card">` elements using template literals assigned to `supplierContainer.innerHTML`. Any supplier with `<` or `"` in `SupplierCode` or `SupplierName` could inject arbitrary HTML/JS. Furthermore, rapid group switching had no `AbortController` or sequence check, and unchecked/re-rendered cards lost prior selections.
- **Fix:**
  - Replaced all `innerHTML` assignments with `buildSupplierCardElement(supplier, isChecked)` and `renderSupplierStatusState(...)` using `document.createElement`, `textContent`, and `replaceChildren()`.
  - Added `activeSupplierRequestController` (`AbortController`), `latestSupplierRequestSeq`, and `preservedSupplierIds` (`Set<string>`) to cancel stale requests and preserve valid selections across group changes.

### 3.2. F02 — Non-Destructive Score Model Binding (`Controllers/EvaluationController.cs`, `Services/EvaluationService.cs`)
- **Root Cause:** `EvaluationController.Save` passed `EvaluationScoreInputViewModel` directly to `EvaluationService.SaveAsync` without checking `ModelState.IsValid`. When an evaluator typed non-numeric text (e.g., `"abc"`) or an out-of-range number, ASP.NET Core model binding failed for that `decimal?` entry and left it `null` (or omitted), which `EvaluationService.SaveAsync` treated as an instruction to `Remove(existing)` from `EvaluationScores`.
- **Fix:**
  - `EvaluationController.Save` now inspects `ModelState.IsValid`, extracts raw posted values from `Request.Form`, populates `EvaluationCellViewModel.RawInput` and `FieldError`, and re-renders `Views/Evaluation/Index.cshtml` with HTTP 200 without touching the database.
  - Added `ClearedCells` hidden inputs (`Rows[i].ClearedCells[criteriaId]`) in `Views/Evaluation/Index.cshtml` and `EvaluationScoreInputRowViewModel` so an existing score is deleted **only** when explicitly cleared by the user (`ClearedCells[criteriaId] == true`), never when omitted in a partial payload.
  - Added change tracking (`hasAnyScoreChange`) in `EvaluationService.SaveAsync` so saving identical scores is a true no-op that preserves existing `TopsisResults` and `Approvals`.

### 3.3. F03 — Unified Aggregate Concurrency & SQL State Locks (`Services/BatchConcurrencyHelper.cs`, `database/01_schema.sql`)
- **Root Cause:** Optimistic concurrency (`RowVersion`) was defined only on `EvaluationBatches`. Mutations to child tables (`EvaluationScores`, `AHPPairwiseComparisons`, `AHPResults`, `TOPSISResults`, `Approvals`) did not force an `UPDATE` on the parent `EvaluationBatch` row with `WHERE RowVersion = @expected`, allowing lost updates and race conditions between score edits and batch approval/cancellation. In addition, SQL triggers validated batch membership but did not reject child writes when the batch was `Completed` or `Cancelled`.
- **Fix:**
  - Created `BatchConcurrencyHelper.BumpAndVerifyBatchVersionAsync` which executes a raw parameterized `UPDATE dbo.EvaluationBatches SET Status = ... WHERE BatchID = @p0 AND RowVersion = @p1` on relational databases (and byte-sequence comparison on InMemory tests) inside the active transaction. If affected rows `== 0`, it throws `DbUpdateConcurrencyException`, which is translated into a user-friendly `BusinessRuleException`.
  - Wired `RowVersion` hidden inputs across `Evaluation/Index.cshtml`, `AHP/Index.cshtml`, `TOPSIS/Index.cshtml`, `DecisionResult/Index.cshtml`, and `EvaluationBatch/Details.cshtml`.
  - Updated SQL triggers (`TR_EvaluationBatchSuppliers_ValidateScope`, `TR_EvaluationBatchCriteria_ValidateScope`, `TR_EvaluationScores_ValidateBatchScope`, `TR_AHPPairwiseComparisons_ValidateBatchScope`, `TR_AHPCriteriaWeights_ValidateBatchScope`, `TR_TOPSISResults_ValidateBatchScope`, `TR_Approvals_ValidateSelectedSupplier`) across `database/01_schema.sql`, `database/scripts/Run_All.sql`, `database/scripts/07_Triggers.sql`, and `database/patches/20261023_trigger_batch_state_locks.sql` to block any write when the batch is `Completed` or `Cancelled`.

### 3.4. F04 — Live Cookie Principal Validation (`Program.cs`, `Services/UserCookieSecurityStamp.cs`, `Controllers/AccountController.cs`)
- **Root Cause:** Cookie authentication relied solely on claims minted at login. Locking/deactivating an account, demoting a user's role, or resetting a password did not revoke or update existing cookies.
- **Fix:**
  - Added `UserCookieSecurityStamp.Compute(User)` (SHA-256 over `UserId`, `Status`, `Role`, and `PasswordHash`) stored in claim `dss:security_stamp`.
  - Configured `CookieAuthenticationOptions.Events.OnValidatePrincipal` in `Program.cs` to query the user (`AsNoTracking`) on every request:
    - If the user is missing, not `Active`, or the `PasswordHash` portion of the stamp changed, `context.RejectPrincipal()` and `SignOutAsync` are called immediately.
    - If the user's `Role` or `FullName` changed while remaining `Active`, the principal's claims are replaced in-place and re-issued (`context.ShouldRenew = true`), enforcing immediate RBAC updates without requiring re-login.
  - Added `ReturnUrl` hidden field in `Views/Account/Login.cshtml` and `Url.IsLocalUrl(model.ReturnUrl)` redirection in `AccountController.Login`.

### 3.5. F05 & F06 — Immutable Decision History & Self-Contained Frozen Snapshots (`Services/DecisionResultService.cs`, `Services/ReportService.cs`)
- **Root Cause:**
  - `EvaluationService.SaveAsync` and `AHPService.SaveComparisonsAsync` deleted non-final `Approvals` rows via `RemoveRange`, destroying the audit trail of prior manager rejections and re-evaluation requests.
  - `BatchRoundSnapshots` stored only minimal IDs and weights. When a batch reached `Completed`, `DecisionResultService.GetResultAsync` and `ReportService.LoadReportDataAsync` still joined live `Suppliers` and `Criteria` tables and re-ran `TOPSISService.GetWorkspaceAsync`. Renaming a supplier or criterion after batch completion altered historical decision screens and regenerated reports.
- **Fix:**
  - Eliminated `RemoveRange` on `Approvals`. Non-final `Approvals` are preserved append-only and annotated with `[Superseded at ...]` when underlying scores or AHP comparisons change.
  - Upgraded `BatchRoundSnapshotData` (`SchemaVersion = 2`) to capture full supplier codes/names, criterion codes/names/types/units, raw score cells, AHP weights and consistency metrics, TOPSIS normalized/weighted matrices, PIS/NIS, distances, rankings, and sensitivity stability summary.
  - Updated `DecisionResultService.GetResultAsync` and `ReportService.LoadReportDataAsync` to reconstruct completed batch results and PDF/Excel exports directly from the frozen `FinalApproval` snapshot (`IsFrozenFromSnapshot = true`).
  - Added **Decision & approval history** and **Evaluation round snapshots** tables to `Views/DecisionResult/Index.cshtml`.
